# 밥때 · 서버 없는 아이폰 앱

전북대학교 **직영관** 주간 식단을 아이폰에 저장하고 iOS 로컬 알림을 예약하는 SwiftUI 앱입니다. 기존 `meal-alarm` 웹 앱과 별개이며 Node 서버, Render, GitHub 업로드, Push 키가 필요하지 않습니다.

## 동작

- 앱을 열면 학교 직영관 주간 식단을 내려받아 파일로 저장합니다. ‘갱신’으로 다시 받을 수도 있습니다.
- 최초 ‘이 아이폰에 알림 예약’을 눌러 권한을 허용하면, 저장된 메뉴가 있는 미래 끼니만 한국 시간 **07:30 / 11:30 / 17:30**에 예약합니다.
- 현재 시각은 아이폰 시계를 사용합니다. 지연 타이머나 백그라운드 상시 실행을 사용하지 않습니다. 해외에서도 Asia/Seoul 기준입니다.
- 알림 본문에는 해당 끼니의 메뉴를 모두 줄바꿈으로 담습니다. 잠금 화면에서 접혀 보일 수 있으므로 길게 눌러 펼치거나 앱을 열어 확인하세요.
- 빈 칸, 미급식, 휴업·공휴일 안내는 제외합니다. 날짜·직영관 여부가 불분명한 페이지는 저장하지 않습니다. 학교에 실제 메뉴가 게시되어 있으면 휴일이어도 그 식단을 따릅니다.
- 같은 날짜·끼니의 예약을 교체하여 중복 예약을 피합니다. 끼니별로 끌 수 있습니다.
- 인터넷 연결이 실패하면 기존 파일과 예약을 유지합니다. 저장된 알림은 인터넷 없이 OS가 처리합니다.
- **매주 새 식단을 받을 때 앱을 열어야 합니다.** 앱을 전혀 열지 않아도 매주 자동 다운로드되는 기능은 없습니다. 마지막 저장 주가 끝나면 새로 갱신할 때까지 식단 알림이 없습니다.

## 비용·무료 설치 조건부터 확인하세요

서버 운영비는 없습니다. 맥북의 Xcode를 사용해 자신의 아이폰에 설치할 수 있습니다. Xcode 자체는 무료입니다.

**무료 Apple 계정(Personal Team)으로 서명한 개발용 앱은 통상 7일 후 서명이 만료됩니다.** 앱을 계속 사용하려면 맥북에서 다시 빌드·설치해야 합니다. 같은 Bundle Identifier와 Team으로 기존 앱 위에 설치하고, 설치 전에 앱을 삭제하지 마세요. 데이터 유지 여부를 확인하고 앱에서 갱신·알림 재예약을 진행하세요. 무료 설치의 제한은 Apple의 현재 정책을 따릅니다.

매주 맥북에서 다시 설치하지 않으려면 Apple Developer Program 등 별도의 배포 방법과 해당 비용·유효기간을 검토해야 합니다. **상시 서버비가 없다는 것이 Apple의 앱 서명·배포 조건까지 없다는 뜻은 아닙니다.** 이 프로젝트는 Apple 계정 가입·결제·App Store 등록을 수행하지 않습니다.

## 맥북 → 아이폰 설치 순서

1. 맥북 App Store에서 **Xcode**를 설치하고 한 번 실행해 필요한 추가 구성요소를 설치합니다. Xcode 15 이상(가능하면 맥과 호환되는 최신판)을 사용하세요. iPhone 대상 버전은 iOS 16 이상입니다.
2. 제공 ZIP을 압축 해제하고 **`BapTime.xcodeproj`를 더블클릭**합니다. 이전 웹 앱 ZIP과 다른 파일입니다.
3. Xcode → Settings → Accounts에서 본인의 Apple 계정으로 로그인합니다. 계정 비밀번호를 채팅에 보내지 마세요.
4. 왼쪽 파란 프로젝트 아이콘 → TARGETS의 **BapTime** → **Signing & Capabilities**로 이동합니다.
5. Automatically manage signing을 켜고 Team을 본인의 **Personal Team**으로 고릅니다.
6. Bundle Identifier의 `com.example.baptime`을 `com.자신만의영문이름.baptime`처럼 본인만의 값으로 변경합니다. 이후 재설치할 때 같은 값을 유지하세요.
7. 아이폰을 USB 케이블로 연결하고 아이폰의 ‘이 컴퓨터를 신뢰’를 허용합니다. 아이폰 설정 → 개인정보 보호 및 보안 → **개발자 모드**를 켜고 요청 시 재시동합니다.
8. Xcode 상단 실행 대상에서 시뮬레이터 대신 본인의 아이폰을 선택하고 **▶ Run**을 누릅니다.
9. 아이폰에서 신뢰 안내가 나오면 설정 → 일반 → VPN 및 기기 관리에서 본인의 개발자 앱을 신뢰합니다. 표시 경로는 iOS 버전에 따라 다를 수 있습니다.
10. 앱에서 실제 직영관 날짜와 메뉴를 확인하고 **‘이 아이폰에 알림 예약’ → 허용**을 누릅니다. 앞으로 남은 알림 개수가 표시됩니다.
11. 앱을 닫고 다음 끼니 시각에 실제 알림을 확인하세요. 집중 모드, 알림 표시·소리 설정은 아이폰 설정을 따릅니다.

시뮬레이터로 화면을 먼저 볼 수도 있지만 실제 아이폰 알림 수신 검증을 대신하지 않습니다. Xcode 설치/서명에서 오류가 나면 오류 문구를 확인해 해결해야 합니다.

## 검증과 한계

현재 클라우드는 Linux여서 **Swift/iOS SDK 빌드, Xcode 서명, 실제 기기 알림 수신은 실행하지 못했습니다.** 아직 실기기에서 완성 검증된 앱으로 간주하면 안 됩니다.

앱 번들에 포함한 `MealParser.js` 자체를 Chromium에서 실제 학교 HTML fixture로 실행했습니다. 7일 날짜 매핑, 전체 메뉴(8/6/6), 빈 식단 제외, 다른 관 차단, 날짜 불일치 차단, 공휴일 미급식 제외 검증이 통과했습니다. 학교의 HTML은 DOMParser로 파싱하며 학교 스크립트를 실행하지 않습니다.

맥북에서 컴파일만 먼저 확인하려면 이 폴더에서 아래 명령을 실행합니다.

```sh
xcodebuild -project BapTime.xcodeproj -target BapTime -configuration Debug -sdk iphonesimulator CODE_SIGNING_ALLOWED=NO build
```

이후 Xcode에서 본인의 아이폰을 선택해 실제 설치와 알림을 확인해야 합니다. 이 명령을 클라우드에서 통과했다고 주장하지 않습니다.

분석기 재검증(선택): Node와 Playwright/Chromium이 설치된 환경에서 `node tests/parser.test.cjs`. 필요하면 `PLAYWRIGHT_MODULE`과 `CHROMIUM_PATH`로 기존 설치 경로를 지정합니다. 테스트 fixture는 2026-10-26에 확인했던 공개 직영관 주간 식단 부분입니다.

아이폰 로컬 알림은 사용자가 허용한 알림 설정과 OS 정책에 따릅니다. 앱 강제 종료 상태에서도 예약 자체는 OS가 관리하지만 무음·집중 모드에서 반드시 소리가 난다고 보장하지 않습니다. 시계 변경이나 권한 변경 후에는 앱에서 다시 예약하세요.
